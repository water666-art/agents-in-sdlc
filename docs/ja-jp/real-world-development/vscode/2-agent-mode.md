アプリケーションの簡単な更新でも、通常は複数のファイルを変更し、テストを実行するなどの作業が必要です。開発者は通常、必要なファイルを探し、変更を加え、テストを実行し、デバッグし、変更し忘れたファイルに気付いて、さらに更新する、といった作業を繰り返します。

こうした作業に役立つのが Copilot エージェントモードです。

Copilot エージェントモードは、統合開発環境 (IDE) 内でより自律的に動作するように設計されています。開発者と同じように、まず既存のプロジェクト構成を調べ、必要な更新を行い、テストなどのタスクを実行し、見つかった問題を自動で修正します。エージェントモードを使って、サイトに新機能を追加する方法を見ていきましょう。

> [!NOTE]
> 名前は似ていますが、エージェントモードと cloud agent は異なる操作体験を提供します。エージェントモードは IDE 内でタスクを実行するため、すばやくフィードバックを得て対話できます。cloud agent はチームのメンバーのように非同期で作業し、issue やプルリクエストを通じてやり取りします。

この演習では、次の方法を学びます。

- Copilot エージェントモードを使ってプロジェクトを調べ、関連ファイルを特定し、複数のファイルにまたがる変更を行う方法。
- GitHub Copilot エージェントモードでユーザー インターフェイス (UI) とデータ層にまたがる新機能を実装する方法。
- Copilot エージェントモードが生成した変更とテストを、コードベースにマージする前にレビューする方法。

## シナリオ

ゲームの一覧が増えてきたため、ユーザーがカテゴリと出版社で絞り込めるようにします。前の演習で出版社用ヘルパーを追加しました。ここでは、残りのデータ層、UI、テストの作業を Copilot エージェントモードで完了します。

## Tailspin Toys の Web サイトを実行する

変更を加える前に、現在の機能を把握するため Tailspin Toys の Web サイトを確認します。

この Web サイトは、開発者をテーマにしたボードゲームのクラウドファンディング プラットフォームです。ゲームを一覧表示し、詳細を表示できます。サイトは単一の Astro アプリケーションで、ビルド時にページを静的なハイパーテキスト マークアップ言語 (HTML) としてレンダリングします。ページでは、オブジェクト リレーショナル マッピング (ORM) ツールである Drizzle ORM を通じて frontmatter からローカル SQLite データベースにクエリします。独立したバックエンドのアプリケーション プログラミング インターフェイス (API) やクライアント側 UI フレームワークはありません。再利用可能なデータアクセス ヘルパーは `src/lib/` にあり、インタラクティブ機能は標準のドキュメント オブジェクト モデル (DOM) API を使う小さな Astro `<script>` の範囲内で追加します。

### Web サイトを起動する

Web サイトを簡単に実行できるよう、単一の Astro 開発サーバーを起動する `npm run dev` タスクが用意されています。GitHub Codespace で次の手順を実行します。

1. codespace に戻ります。前の演習を終えた状態では、`main` にいるはずです。
2. <kbd>Control</kbd>+<kbd>`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>`</kbd> (Windows/Linux) を押して、codespace 内に新しいターミナル ウィンドウを開きます。
3. フィルタリング作業用の新しいブランチを作成して切り替えます。

   ```bash
   git checkout main
   git pull
   git checkout -b filtering-vscode
   ```

4. 次のコマンドを実行して Web サイトを起動します。

   ```bash
   npm run dev
   ```

   Astro 開発サーバーの準備ができると、次のような URL を示すバナーが表示されます。

   ```bash
   🚀 Tailspin Toys is ready!
      Astro server: http://localhost:4321
      Press Ctrl-C to stop.
   ```

> [!NOTE]
> `http://localhost:4321` のブラウザー ウィンドウを開くダイアログが表示された場合は、**x** を選択して閉じます。

5. ターミナルで Astro サーバーのアドレス `http://localhost:4321` を選択するときに、<kbd>Command</kbd> (Mac) または <kbd>Ctrl</kbd> (Windows/Linux) を押したままにして、Web サイトを開きます。

> [!NOTE]
> codespace でターミナルから localhost の URL を選択すると、自動的に `https://<your-codespace-name>-4321.app.github.dev/` に転送されます。これは、Web サーバーをホストしている codespace へのプライベート トンネルです。

### Web サイトを確認する

Web サイトが起動したら、機能を確認できます。主な機能は次のとおりです。

- **ホームページ**: ボードゲームのタイトル、画像、説明を一覧表示します。
- **ゲーム詳細ページ**: ゲームを選択すると、タイトル、説明、出版社、カテゴリなどの詳細ページが表示されます。

## Copilot でバックログを確認する

> [!TIP]
> **Copilot Chat を開く**
>
> 以下の演習を始める前に、codespace に戻り、Copilot Chat パネルを開いて **New Chat** を選択し、新しい会話を開始します。使用するモードとモデルは演習ごとに異なるため、必要な場合は各手順で指定します。

Web サイトの初期実装は機能しますが、新しい機能を追加して改善します。まずバックログを確認します。テンプレートからプロジェクトをセットアップすると issue のバックログが自動作成されるため、GitHub Copilot に項目を表示してもらいます。

1. Chat ビューのエージェント ドロップダウンから **Agent** を選択します。**Agent** は自律的に変更の計画とファイルへの実装を行い、ターミナル コマンドを実行してツールを呼び出します。

   ![Chat ビューのエージェント選択を示すスクリーンショット](../../../_images/shared-chat-mode-selector.png)

2. 利用可能なモデルの一覧から **Claude Sonnet 4.5** を選択します。

> [!CAUTION]
> このワークショップの作成者は、特定のモデルを推奨していません。ワークショップの作成時に Claude Sonnet 4.5 を使ったため、指示にはこのモデルを記載しています。これにより、コード提案が比較的一貫し、スムーズに演習を進められることを期待しています。ただし、人工知能 (AI) の大規模言語モデル (LLM) は確率的に動作するため、ワークショップで示す内容と異なる提案が表示されることがあります。これは正常な動作です。

> [!NOTE]
> 大規模言語モデルの確率的な性質により、Copilot が別のモデル コンテキスト プロトコル (MCP) コマンドを使うことがありますが、タスクは完了できるはずです。

3. 次のプロンプトを Copilot に送信し、issue のバックログについて尋ねます。

   ```plaintext
   GitHub リポジトリのバックログにある項目を表示してください。ユーザーにとって特に役立つ項目を優先して並べるのを手伝ってください。
   ```

4. issue をすべて一覧表示するコマンドを実行するため、**Continue** を選択します。
5. 生成された issue の一覧を確認します。

Copilot がユーザーに最も役立つと思われる項目を基に、優先順位も付けていることを確認してください。

## 指示ファイルを確認する

エージェントにコードを生成させる前に、作業に必要なコンテキストを Copilot に提供する指示ファイルを確認します。Web サイトへの機能追加の方法に関するコンテキストが記載された [ユーザー インターフェイス (UI)][ui-instructions] ファイルを使います。

1. codespace で `.github/instructions/ui.instructions.md` を開きます。
2. 機能追加の進め方に関する全体的なガイダンスを確認します。具体的には、次の内容が含まれます。
   - アーキテクチャの概要。
   - コンポーネントの設計、テスト可能性、アクセシビリティに関する原則。
   - Astro、Tailwind CSS、Drizzle など、ファイルの種類ごとの指示ファイルへのリンク。

> [!TIP]
> 指示ファイルから、ほかの指示ファイルやプロジェクト内のファイルを参照できます。パスは指示ファイルがある場所を基準にしています。指示を再利用しやすい小さなファイルに分けたり、複雑な指示を整理したり、コード生成時に従う例やテンプレートを Copilot に示したりできます。

[ui-instructions]: https://github.com/github-samples/tailspin-toys/blob/main/.github/instructions/ui.instructions.md

## フィルタリング機能を実装する

フィルタリングを完了するには、アプリケーションに少なくとも 3 つの変更が必要です。

- データ層 (`src/lib/`) の残りのフィルタリング ロジックを追加または改善します。
- フィルタリングの動作を検証するテストを追加または更新します。
- ゲーム一覧ページを更新し、フィルタリング UI を追加します。

さらに、コードベースにマージする前にテストを実行し、成功することを確認する必要があります。Copilot エージェントモードにこれらのタスクを実行してもらいましょう。

1. Copilot との現在の会話を続けるか、**New Chat** を選択して新しい会話を開始します。
2. **Add Context**、**Instructions**、**ui** の順に選択し、指示ファイルを指定します。

   ![UI 指示ファイルの選択例を示すスクリーンショット](../../../_images/ex3-select-instructions-file.png)

3. Chat ビューのエージェント ドロップダウンで **Agent** が選択されていることを確認します。

   ![Chat ビューのエージェント選択を示すスクリーンショット](../../../_images/shared-chat-mode-selector.png)

4. モデルとして **Claude Sonnet 4.5** が引き続き選択されていることを確認します。
5. バックログの関連 issue の要件に基づいて機能を実装するよう、次のプロンプトで Copilot に依頼します。

   ```plaintext
   関連する GitHub issue の要件に基づいて、出版社とカテゴリで絞り込めるようにサイトを更新してください。前の演習で追加した出版社用ヘルパーは維持し、必要に応じて改善しながら、残りのデータ層、UI、テストを完了してください。完了前にすべてのテストが成功することを確認してください。サーバーはすでに実行中なので、起動する必要はありません。
   ```

6. Copilot がプロジェクトを調べ、機能に関係するファイルを特定する様子を確認します。データ層のヘルパーと UI、テストを探した後、ファイルを変更してテストを実行します。

   ![Copilot がプロジェクト ファイルを調べる様子を示すスクリーンショット](../../../_images/ex3-agent-mode-explores.png)

> [!NOTE]
> Copilot はプロジェクトの調査、ファイルの変更、テストの実行など、複数のタスクを実行します。タスクやコードベースの複雑さに応じて、数分かかることがあります。作業中に、コード エディターに **Keep** と **Undo** のボタンが表示される場合があります。Copilot が完了するとすべての変更に対して **Keep** または **Undo** が表示されるため、作業中に選択する必要はありません。

7. Copilot に求められたら **Continue** を選択し、テストを実行します。

   ![Copilot Chat ペインにテスト実行の確認ダイアログが表示されているスクリーンショット](../../../_images/ex3-agent-mode-run-tests.png)

8. 作業中に処理が一時停止したり、テストに失敗したりすることがあります。問題ありません。Copilot はコード生成とテストを繰り返し、問題を検出しなくなるまで作業します。

   ![Copilot エージェントモードの完了した Chat セッションを示すスクリーンショット](../../../_images/ex3-agent-mode-proposed-changes.png)

9. 生成されたコードを確認し、問題がないか調べます。

> [!CAUTION]
> Copilot などの AI ツールが生成したコードも、必ずレビューしてください。

10. Web サイトを開いているブラウザーに戻り、新しい機能を確認します。
11. すべてが動作し、コードのレビューも完了したら、Copilot Chat ウィンドウで **Keep** を選択します。

### 追加の演習 - ページングを実装する

ゲームの一覧が増えると、ページングが必要になります。この演習で学んだことを使い、Copilot にサイトのページングを実装するよう依頼します。コードを作成するときは、次の点を考慮してください。

- 指示ファイルなど、既存のベスト プラクティスに従います。
- ユーザーがページ サイズを選択できるようにするか、固定値にするかなど、ページングの実装方法を検討します。
- 望む実装に必要なガイダンスを Copilot に提供するプロンプトを作成します。
- GitHub Copilot に変更やコンテキストの追加を依頼して、何度か調整することもあります。Copilot を使うときの通常の進め方です。
