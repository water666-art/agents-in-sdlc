GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを実行するなど、自律的に作業します。作業は手元のマシン上でリアルタイムに進むため、VS Code の Copilot Chat では、各ツールの呼び出しやファイルの編集をその場で確認できます。差分をインラインでレビューし、個々の変更を受け入れるか取り消すか選べます。また、エディターを離れずに追加のプロンプトを送って、作業を調整したり広げたりできます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューし、受け入れます。
- セッションの途中でエージェントに追加指示を送り、高コントラストモードにライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタム エージェントが、高コントラストモードを実装しています。作業中にデザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいとのことです。新しい会話を始めず、進行中のセッションに追加指示を送って作業を広げます。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが行う各ステップが表示されます。調べたファイル、実行したコマンド、提案した編集を確認できます。各ファイルの編集は差分としてチャット内に表示され、**Keep** と **Undo** の操作ができます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行しようとするターミナル コマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると、変更を受け入れます。
   - **Undo** を選択すると、変更を取り消し、エージェントに再試行させます。
4. チャット上部の **Files changed** の表示を開くと、このセッションでエージェントが変更したファイル一式を確認できます。

> [!NOTE]
> ツールの使用に許可が必要な場合（たとえばターミナル コマンドの実行）、エージェントは一時停止して **Allow** の確認を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントが高コントラストモードの実装を終えるまで待ちます。完了すると、変更内容をまとめたメッセージが表示されます。

## エージェントにライトモードの追加を指示する

高コントラストモードが追加されたら、同じ会話を続けてライトモードの切り替えを追加します。同じチャット セッションを続けることで、エージェントは前の作業で触れたコンポーネント、スタイルの方法、設定を local storage に保存する方法を含むコンテキストを保持できます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    いいですね。次に、高コントラスト切り替えと並べてライトモードの切り替えを追加してください。ライトモードも同じ方式にして、設定を local storage に保存し、同じユーザー インターフェイス (UI) 領域から切り替えられるようにしてください。高コントラストとライトモードは、それぞれ独立して有効にできるようにしてください。
    ```

2. エージェントは、すでに行った変更を確認し、ライトモードの追加を提案して作業を再開します。
3. 高コントラストモードのときと同様に、新しい編集を確認しながら **Keep** または **Undo** を選択します。
4. エージェントの方向性が意図と異なる場合（たとえば、希望しない方法で切り替え UI のリファクタリングを始めた場合）は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送信します。

> [!TIP]
> 進行中のセッションに追加指示を送ると、最初からやり直すより効率的です。追加プロンプトを使って調整（「CSS を簡潔にしてください。セレクターを複製せず、CSS 変数を使ってください」）、軌道修正（「切り替えを 3 つにせず、既存の設定パネルにライトモードを組み込んでください」）、範囲の拡張（「両方の切り替えにキーボード ショートカットも追加してください」）ができます。

## 変更されたファイルをレビューする

作業をコミットする前に、エージェントが変更したすべての内容を確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更したファイルをいくつか開き、差分を確認します。カスタム エージェントのアクセシビリティ パターンが反映されていることを確認します。Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、local storage による設定の保存などが対象です。
4. 内容に問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、方向付けしました。ファイルの編集をその場でレビューし、受け入れるか取り消すかを選び、追加プロンプトでコンテキストを保ったまま作業を広げました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を受け入れるか取り消すか選びました。
- 追加プロンプトを使って、セッションの途中でエージェントに指示しました。
